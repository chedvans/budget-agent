# יועץ התקציב: אג'נט לניהול תקציב חודשי

> **מה מיוחד כאן: מתכוננים לחג לפי הלוח העברי.**
> כותבים "אני רוצה להתכונן לפסח", והיועץ שואל כמה כסף צריך, מחשב לפי הלוח העברי כמה חודשים נשארו
> עד החג ("פסח, ט״ו ניסן תשפ״ז, בעוד 177 ימים: 6 חודשי חיסכון"), מחלק את הסכום לחודשים, ובונה
> תוכנית קיצוצים חודשית שנבדקת מול התקציב. ההוצאות הגדולות של החגים מגיעות בבת אחת, וזה עוזר להגיע אליהן מוכנים.

## הבעיה ולמה בחרתי בה
בסוף כל חודש רואים שההוצאות היו גבוהות מהמתוכנן, אבל לא ברור **איפה בדיוק** הכסף הלך ו**מה אפשר לשנות בפועל**.
בדיקה ידנית של עשרות עסקאות מול התקציב לוקחת זמן, ובדרך כלל נגמרת בהחלטה כללית כמו "צריך להוציא פחות".
בחרתי בבעיה הזו כי היא יומיומית, יש בה נתונים אמיתיים לעבוד איתם, וכי הפתרון דורש שיקול דעת ולא רק חישוב.
בנוסף, הרבה משפחות מכירות את הלחץ של לפני החגים, כשהוצאות גדולות מגיעות בבת אחת. לכן הוספתי ליועץ
יכולת לתכנן חיסכון לקראת חג, לפי התאריך האמיתי בלוח העברי.

## מה האג'נט עושה
האג'נט מקבל מטרה בשפה חופשית, למשל: *"מצא תוכנית מציאותית לחסוך 1,500 ש"ח בחודש הבא"*, וקובצי הוצאות ותקציב.
הוא מחליט בעצמו על סדר הפעולות: טוען נתונים, משווה לתקציב, נכנס לעסקאות בקטגוריות שבהן הייתה חריגה כדי להבין
ממה היא נבעה (למשל 5 משלוחי אוכל בחודש), בונה תוכנית קיצוצים, **בודק אותה** בכלי סימולציה, ואם היא לא מגיעה ליעד
או לא מציאותית הוא מתקן ובודק שוב. בסוף הוא מחזיר דוח עם פעולות מעשיות, או מדווח ביושר שהיעד לא בר-השגה.

**לקראת חג** האג'נט משלב שני סוגי כלים: כלי תאריכים (`holiday_countdown`, שמחשב לפי הלוח העברי כמה חודשי חיסכון
נשארו וכמה לחסוך בכל חודש) עם כלי התקציב. אם חסר לו מידע, למשל כמה כסף צריך לחג, הוא שואל ולא ממציא.
בממשק יש באנר בולט עם ספירה לאחור לחגים הקרובים, וכפתור שמתחיל את התכנון בלחיצה אחת.

| רכיב | איך הוא ממומש |
|------|---------------|
| **קבלת מטרה** | `--goal` בשפה חופשית, נשלח למודל יחד עם נתיבי הקבצים |
| **קבלת החלטות** | מודל Gemini בוחר בכל צעד איזה כלי להפעיל (function calling) |
| **כלים** | `load_expenses`, `load_budget`, `compare_to_budget`, `get_transactions`, `find_recurring`, `simulate_savings_plan`, `holiday_countdown` |
| **בחינת התוצאה** | `simulate_savings_plan` מחזיר `target_reached`, `missing` ו-`problems`, והמודל מתקן לפיהם |
| **תנאי סיום** | הכלי `finish`. הצלחה מתקבלת רק אחרי שהתוכנית אומתה בסימולציה. עצירה בכישלון אחרי `--max-steps` צעדים |

## החלטות תכנון
- **המוח מחליט, הקוד מוודא.** המודל בוחר את הצעדים, אבל הכללים שאסור לטעות בהם נאכפים בקוד:
  אי אפשר לקצץ בהוצאה קבועה (שכירות), לא יותר מ-10% מהוצאה חיונית, ולא יותר מ-60% מהוצאה אחרת.
  אם המודל מנסה להכריז על הצלחה לפני שבדק את התוכנית, הלולאה דוחה את הסיום ומחזירה לו הודעה.
- **כלים לא מפילים את התוכנית.** כל שגיאה (קובץ חסר, שורה פגומה ב-CSV, קטגוריה לא קיימת, ארגומנט שגוי)
  חוזרת למודל כ-`{"error": ...}`, והוא מחליט איך להמשיך. בקובץ הדוגמה יש בכוונה שורה פגומה.
- **חיבור ל-Gemini.** משתמשים בממשק התואם-OpenAI של Gemini (ספריית `openai` עם `base_url` של Google).
  כך הקוד נשאר פשוט, ואפשר להחליף ספק מודל בשינוי של שורה אחת. בכל תשובה של Gemini לקריאת כלי
  מצורפת "חתימת מחשבה", והקוד מחזיר אותה כמו שהיא בבקשה הבאה (ראו `_assistant_message`).
- **שגיאות תקשורת.** בשגיאות רשת או עומס יש ניסיונות חוזרים עם המתנה.
  מפתח שגוי או שם מודל שגוי עוצרים מיד עם הודעה ברורה.
- **תאריכים מחושבים, לא מנוחשים.** מודל שפה עלול לטעות בתאריך של פסח או לא לדעת שתשפ"ז שנה מעוברת
  (ולכן פורים באדר ב'). לכן התאריכים מחושבים בכלי עם הספרייה `pyluach`, וגם החלוקה לחודשים נעשית בקוד.
  המודל רק מחליט מתי להשתמש בכלי.
- **מה האג'נט לא עושה:** הוא לא מבצע פעולות כספיות ולא מבטל מנויים בעצמו, אלא רק ממליץ.
  במקרה הזה ההחלטה צריכה להישאר בידי המשתמש.

## התקנה והרצה
דרוש Python 3.9 ומעלה.

```bash
pip install -r requirements.txt
```

הגדרת המפתח והמודל:
1. יוצרים מפתח ב-[Google AI Studio](https://aistudio.google.com/apikey).
2. מעתיקים את `.env.example` לקובץ בשם `.env` (ב-Windows: `copy .env.example .env`).
3. ממלאים בקובץ `.env`:
```
GEMINI_API_KEY=המפתח-שלכם
GEMINI_MODEL=gemini-3.5-flash-lite
```
אפשר גם להחליף מודל בהרצה אחת בלבד: `python agent.py --model <שם-מודל>`.

### ממשק צ'אט בדפדפן
```bash
python -m streamlit run app.py
```
ייפתח דפדפן עם חלון שיחה. אפשר לשאול שאלות ("איפה חרגתי מהתקציב?") או לבקש תוכנית חיסכון,
ולראות את הצעדים שהאג'נט בחר. בסרגל הצד אפשר להעלות קובצי הוצאות ותקציב משלכם.
השיחה נמשכת: האג'נט זוכר מה כבר נבדק, ואם חסר לו מידע הוא שואל.

### הרצה בטרמינל
הרצה עם נתוני הדוגמה:
```bash
python agent.py
```

הרצה עם מטרה וקבצים משלכם:
```bash
python agent.py --goal "אני רוצה לחסוך 800 ש\"ח בחודש" --expenses my.csv --budget my_budget.json --max-steps 20
```

פלט כל ריצה נשמר אוטומטית בתיקייה `runs/`.

### בדיקות (לא צריך מפתח API)
```bash
python -m unittest discover tests -v
```
הבדיקות מחליפות את Gemini ב"מוח" מדומה ובודקות את הלולאה, את דחיית הסיום המוקדם, את העצירה אחרי מספר צעדים ואת הטיפול בשגיאות.

## פורמט הקבצים
**הוצאות (CSV):** `date,description,category,amount`.
התאריך בפורמט `2026-11-01`, הסכום מספר בלבד, והקטגוריה כתובה בדיוק כמו בקובץ התקציב.
ב-Excel שומרים כ-**CSV UTF-8**.

**תקציב (JSON):**
```json
{"monthly_income": 13500,
 "categories": {"מזון": {"limit": 2800, "essential": true},
                "שכירות": {"limit": 4200, "essential": true, "fixed": true}}}
```

### ריצה בטרמינל

הפלט המלא נמצא בקובץ [`sample_run.txt`](sample_run.txt).
בריצה רואים את האג'נט מחליט ומתקן את עצמו: התוכנית הראשונה הגיעה רק ל-1,300 ש"ח
ונדחתה בגלל קיצוץ לא מציאותי במנויים (63%). האג'נט קרא את הבעיה, תיקן את התוכנית
והגיע ליעד של 1,500 ש"ח, ורק אז סיים.

## מבנה הפרויקט
```
agent.py          המוח והלולאה: החיבור ל-Gemini, ההחלטות ותנאי הסיום. משמש גם להרצה מהטרמינל
tools.py          הכלים שהאג'נט יכול להפעיל
app.py            ממשק הצ'אט בדפדפן (Streamlit), משתמש באותה לולאה מ-agent.py
data/             נתוני דוגמה: הוצאות (CSV) ותקציב (JSON), כולל שורה פגומה בכוונה
tests/            בדיקות אוטומטיות
screenshots/      צילומי מסך של הממשק
sample_run.txt    פלט של ריצה מלאה בטרמינל
```

ההפרדה לשלושה קבצים מקבילה לשלושת חלקי האג'נט: **מוח ולולאה** (`agent.py`), **כלים** (`tools.py`),
וממשק למשתמש (`app.py`). הטרמינל והממשק משתמשים באותה לולאה, כך שההתנהגות זהה בשניהם.
